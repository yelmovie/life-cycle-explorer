# PRD — 생명 시계 연구실

- 프로젝트명: **생명 시계 연구실**
- 영문명: **Life Clock Lab**
- Repository: `life-clock-lab`
- GitHub Description: `Interactive elementary science game for exploring life cycles through observation, experiments, simulation, comparison, and digital creation.`
- 대상: 초등학교 3학년
- 교과/학기: 과학 3학년 1학기 「생물의 한살이」
- 구조: **5 Stages / 10 Screens**
- 플랫폼: Tablet-first Web / PWA, 16:9 가로형
- Science World 영역: 생명의 숲
- 권장 플레이 시간: 30~40분
- 문서 버전: 1.0
- 작성일: 2026-08-24

## 1. 제품 한 줄 정의
학생이 생물의 성장 순서를 외우는 대신 **관찰 → 시간 비교 → 실험 설계 → 시간 가속 → 데이터 해석 → 생물 비교 → 디지털 기록 제작**을 수행하며 생물의 한살이를 탐구하는 태블릿 과학 게임.

## 2. 문제 정의
「생물의 한살이」는 실제 사육·관찰, 씨앗과 식물의 조건 실험, 여러 생물의 한살이 비교, 소개 자료 제작이 핵심이다. 따라서 종이 활동지나 PPT 퀴즈를 그대로 태블릿으로 옮기는 방식은 디지털 사용 이유가 약하다.

본 제품은 다음과 같은 디지털 고유 가치를 제공한다.

1. 같은 생물의 여러 시점을 시간축에서 앞뒤로 반복 비교한다.
2. 확대·주석·전후 겹쳐보기로 관찰 증거를 직접 남긴다.
3. A/B 실험의 조건을 학생이 직접 구성하고 공정한 비교인지 검증한다.
4. 실제로 며칠이 걸리는 발아·성장 변화를 교육용 시간 가속으로 반복 관찰한다.
5. 흙 속 뿌리와 싹의 변화를 3D 투명 토양 단면에서 관찰한다.
6. 스마트 온실에서 센서를 공간에 설치하고 조건 데이터를 보고 판단한다.
7. 두 생물의 한살이를 같은 기준으로 비교한다.
8. 앞에서 모은 자료를 재사용해 한살이 소개 자료를 직접 제작한다.
9. 실패를 삭제하지 않고 실험 기록으로 남겨 수정과 재실험을 유도한다.

### 실제 관찰과의 관계
[4과04-01]은 동물의 한살이를 **직접 관찰**하는 성취기준이다. 이 웹 콘텐츠는 실제 사육 관찰을 완전히 대체한다고 주장하지 않는다. 수업에서는 실제 관찰과 연결하고, 태블릿은 확대 비교·날짜별 기록·그림/주석·선택적 사진 저장을 지원하는 **관찰 기록 도구이자 디지털 보조 탐구 환경**으로 사용한다.

## 3. 적용 성취기준
2025학년도 적용 성취기준 자료의 「생물의 한살이」 영역을 기준으로 한다.

- **[4과04-01]** 동물의 한살이를 직접 관찰하고, 관찰한 내용을 글과 그림으로 표현할 수 있다.
- **[4과04-02]** 식물이 자라는 데 필요한 조건을 찾는 실험을 설계하여 수행할 수 있다.
- **[4과04-03]** 생물의 한살이 과정을 조사하여 생물에 따라 한살이의 유형이 다양함을 소개하는 자료를 만들어 공유할 수 있다.

> 코드의 `4과`는 3~4학년군 성취기준 코드이며, 첨부 수업자료에서는 이 단원이 3학년 1학기 4단원으로 제시되어 있다.

## 4. 첨부자료에서 확인한 단원 핵심

### 직접 반영할 학습 내용
- 배추흰나비의 한살이 관찰과 단계 변화
- 씨가 싹 트는 데 필요한 조건: **물과 알맞은 온도**
- 식물이 잘 자라는 데 필요한 조건: **햇빛과 적당한 양의 물**
- 실험 설계 시 **알아보려는 조건만 다르게 하고 나머지 조건은 같게** 하는 비교 원리
- 알을 낳는 동물과 새끼를 낳는 동물의 한살이 비교
- 한해살이식물과 여러해살이식물의 한살이 비교
- 생물의 한살이 소개 자료 만들기와 공유
- 스마트 화분/스마트팜 발상
- 조사 내용을 순서화하여 다큐멘터리·소개 자료로 만드는 흐름

### 벤치마킹만 할 요소
- 딱지·무한변신카드: 단계가 이어져 변화해 보이는 조작 원리만 참고
- 폭탄게임: 위험/보상 의사결정의 긴장감만 보조 미션에 참고
- 피라미드·빙고·OX: 핵심 게임으로 사용하지 않음
- 외부 Vrew 제작: `조사 → 순서화 → 설명 → 발표` 흐름만 참고하고 외부 가입 없이 앱 내부 제작으로 재설계

### 복제 금지
첨부자료의 화면 디자인, 문항, 도안, 게임 규칙, 이미지 구성, 문구를 그대로 복제하지 않는다.

- 문장 길이

## 6. 세계관
미래의 생명 연구기지에 있는 중앙 장치 **BIO CLOCK**의 기록이 뒤엉켰다.

뒤엉킨 데이터:
1. 동물의 변화 기록
2. 씨앗 발아 조건 기록
3. 식물 성장 조건 기록
4. 서로 다른 생물의 한살이 기록
5. 생명 기록 아카이브

학생은 **생명 시간 연구원**이 되어 5개의 연구 구역을 복구한다.

Stage 완료 보상:
1. 관찰 링
2. 발아 링
3. 성장 링
4. 다양성 링
5. 기록 링

5개 링이 모두 복구되면 Page 10의 BIO CLOCK이 재가동된다.

## 7. 전체 학습 흐름
**관찰 → 변화 증거 기록 → 시간 순서 추론 → 실험 질문 선택 → A/B 조건 설계 → 시간 가속 → 결과 비교 → 원인 판단 → 성장 조건 분석 → 생물 한살이 비교 → 유형 판단 → 소개 자료 제작 → 공유/엔딩**

## 9. 페이지별 핵심 설계

### Page 01 — 생명 스캔 시작
- 배추흰나비 관찰 자료에서 렌즈·핀치줌·관찰핀으로 증거를 찾는다.
- 관찰한 내용을 그림 또는 짧은 문장으로 남긴다.
- 선택적으로 실제 교실 관찰 사진을 로컬에 추가한다.
- 최소 3개 관찰 증거와 기록 1개 이상이 필요하다.
- 관찰하지 않은 특징은 자동 해금하지 않는다.

### Page 02 — 시간 기록 복원
- 여러 관찰 회차를 시간축에서 앞뒤로 스크럽한다.
- 두 시점을 Split View 또는 투명도 겹쳐보기로 비교한다.
- 달라진 부분에 원/선/관찰핀을 표시한다.
- 실제 생물의 발달 기간은 환경과 개체에 따라 달라질 수 있으므로 일반화된 정확한 ‘몇 일째’ 수치를 사실처럼 제시하지 않는다.
- 기본은 `관찰 1회차~4회차` 또는 검수된 실제 관찰 날짜를 사용한다.

### Page 03 — 실험 설계 테이블
- 조사 질문: `물이 필요한가?` / `알맞은 온도가 필요한가?`
- 조건: 물 있음/없음, 온도 알맞음/낮음.
- 같은 종류의 씨앗, 같은 수, 같은 용기 등은 동일하게 유지한다.
- 알아보려는 조건 하나만 다르게 해야 실행 가능하다.
- 두 조건이 함께 다르면 “무엇 때문인지 알 수 있을까요?” 피드백을 준다.

### Page 04 — 7일 시간 가속 ★ 핵심 3D
- A/B 투명 배양캡슐을 회전·확대한다.
- 교육용 시간 레버를 움직여 씨앗 → 뿌리/싹 → 어린 식물의 변화를 관찰한다.
- `일반 보기 / 투명 토양 보기`를 전환한다.
- 최소 2개 시점 스냅샷을 저장·비교한 뒤 결론을 제출한다.
- 날짜는 교육용 시뮬레이션 시간이며 실제 모든 씨앗의 발아 시점과 같다고 제시하지 않는다.
- 씨앗 내부 해부학 명칭은 필수 학습으로 넣지 않는다.

### Page 05 — 스마트 온실 복구 ★ 핵심 3D
- 이미 싹튼 식물에 광량 센서, 토양 수분 센서, 자동 급수기, 차광막 등을 설치한다.
- 센서는 `부족 / 적당 / 많음` 같은 범주형 상태를 기본으로 제공한다.
- 햇빛 또는 물 중 하나를 조사 대상으로 정하고 A/B에서 한 조건만 다르게 한다.
- 3D 공간에서 장비의 위치와 역할을 판단하게 한다.

### Page 06 — 성장 결과 분석
- A/B 조건 카드, 성장 스냅샷, 단순 그래프를 함께 본다.
- `어떤 조건이 달랐나 → 어떤 변화가 나타났나 → 그래서 무엇을 말할 수 있나`의 3단 사고를 수행한다.
- 주장 + 조건 증거 + 관찰 증거를 연결해야 완료된다.

### Page 07 — 생명 파일 조사
기본 생물:
- 배추흰나비
- 개구리
- 닭
- 개
- 봉숭아
- 사과나무

학생은 두 생물을 비교 슬롯에 넣고 `처음 모습 / 자라는 중 / 다 자람 / 다음 세대` 같은 동일 기준으로 조사한다.
- 동물 비교 1회 이상
- 식물 비교 1회 이상
- 비교 증거 4개 이상

### Page 08 — 생명 패턴 분석
동물:
- 알을 낳는 유형
- 새끼를 낳는 유형

식물:
- 한해살이
- 여러해살이

비교 매트릭스에 증거를 배치하고, 검수된 새 사례 1개에 배운 기준을 적용한다. 정답 선택만으로는 완료되지 않고 근거 증거가 필요하다.

### Page 09 — 생명 기록 제작소
제작 형식:
1. 움직이는 한살이 카드
2. 한살이 미니 다큐/슬라이드

기능:
- 앞 Stage에서 모은 자료를 타임라인에 배치
- 장면 순서 변경
- 짧은 설명
- 그림/주석
- 선택적 음성 녹음
- 미리보기
- PNG 결과 카드 저장

완료 조건:
- 최소 3개 장면
- 2개 이상 특징 설명
- 제목
- 한살이 요약 1문장

### Page 10 — 생명 시계 재가동 ★ 3D FINAL
5개 링:
- 관찰
- 발아
- 성장
- 다양성
- 기록

학생이 각 Stage의 대표 수행 기록을 확인하면 링이 BIO CLOCK에 결합된다.
최종적으로 씨앗 발아, 식물 성장, 꽃·열매, 배추흰나비의 단계 변화가 짧게 연결되며 연구실이 복구된다.

이 화면은 **새 개념 평가가 아니라 종합 확인과 성취감**을 담당한다.

## 10. 상호작용 다양성
렌즈 이동, 핀치줌, 관찰핀, 그리기/주석, 시간축 스크럽, 전후 겹쳐보기, 조사 질문 선택, A/B 실험 설계, 조건 통제 검증, 3D 시간 레버, 투명 토양 보기, 3D 회전, 센서 설치, 장비 스냅, 조건 데이터 판독, 그래프/스냅샷 비교, 주장-증거 연결, 두 생물 동기화 비교, 비교 매트릭스, 새 사례 전이, 타임라인 편집, 캡션 작성, 선택적 음성 녹음, 결과 카드 제작, 3D BIO CLOCK 결합.

## 11. 게임 피드백 원칙

잘못된 방식:
- “틀렸습니다.”
- 빨간 X
- 정답 자동 이동
- 정답 문장 즉시 공개

권장 방식:
- “두 조건이 함께 달라졌어요.”
- “이 결과만으로 무엇 때문인지 알 수 있을까요?”
- “어느 부분을 보고 그렇게 판단했나요?”
- “같은 기준인데 다른 결과가 하나 있어요.”
- “이 증거는 어떤 변화를 보여 주나요?”

## 12. 힌트
1. 관찰 힌트
2. 행동 힌트
3. 부분 시범
4. 직접 안내

힌트를 사용해도 다음 Stage는 막지 않는다.

## 13. 평가
- Stage 1: 관찰 증거, 글/그림 기록, 시점 비교
- Stage 2: 조건 통제, 수정 과정, 결과 비교, 결론-증거 일치
- Stage 3: 센서 설치, 조건 조절, 주장-증거 연결
- Stage 4: 비교 생물 수, 공통점/차이점, 유형 판단 근거
- Stage 5: 순서, 단계 설명, 결과물 완성

별:
- 1별: 핵심 미션 완료
- 2별: 관찰/증거 기록 완성
- 3별: 보너스 비교·재검토·최소 힌트 등 심화 기준

## 14. 3D 적용 원칙
3D는 **Page 04, 05, 10**에만 사용한다.

- Page 04: 시간 변화 + 흙 속 관찰
- Page 05: 센서/장비의 공간 배치
- Page 10: 5개 학습 기록 통합과 엔딩

관찰 기록, 그래프 판독, 비교표, 타임라인 편집은 2D/2.5D가 정보 판독에 유리하므로 3D로 만들지 않는다.

## 15. 비주얼 방향
키워드:
- premium educational science-fantasy
- bright bio research lab
- teal / emerald / science blue / warm yellow / soft gold
- clean data visualization
- miniature lab diorama
- life-cycle clock rings

피하기:
- 공포 실험실
- 과도한 네온 사이버펑크
- 유아용 캐릭터/스티커북
- 이모지 중심 UI
- 카드만 반복되는 화면
- 이미지 안에 한글 UI 굽기
- 불필요한 3D 장식

## 16. UI/UX
- 16:9 태블릿 가로 우선
- 터치 영역 최소 44px, 권장 48px
- 한글은 HTML/CSS/SVG
- 색만으로 상태 전달 금지
- Pointer Events 기반
- hover 전용 기능 금지
- Undo/Reset 제공
- reduced motion 제공
- 조작 설명은 1~2문장 + 짧은 시범

## 18. 개인정보
- 이름/학번 서버 저장 기본 요구사항 아님

- 카메라/마이크는 버튼을 눌렀을 때만 요청
- 권한 거부 시에도 완주 가능
- 생성형 AI API 키 클라이언트 포함 금지
- 결과 공유 시 개인정보 자동 포함 금지

## 20. 제품 완료 기준

- Page 04, 05, 10만 핵심 3D
- [4과04-01]~[4과04-03] 모두 수행형 행동으로 연결
- 모든 Stage를 OX/객관식만으로 완료할 수 없음
- 새로고침 후 상태 복원
- 카메라/마이크 없이 완주

- 저사양 태블릿 핵심 경로 30fps 목표
- 최종 MissionResult 생성
