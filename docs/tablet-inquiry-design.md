# 생명 시계 연구실 태블릿 탐구 경험 설계

2026년 10월 16일 · 기능과 화면 설계안 · 대상: 현재 adventure 버전

학생이 시간을 움직이고, 조건을 바꾸고, 자기 관찰 증거를 비교하며 생물의 한살이를 설명하는 경험을 만든다. 대표 장면은 **씨앗 실험을 복제해 조건 하나를 바꾸고 이전 결과와 비교하는 장면**, **두 식물의 시간을 다음 해 봄까지 함께 넘기는 장면**이다. 기존 다섯 구역과 열 개 활동, 숲색과 크림색의 미술 방향을 활용한다.

현재 실행 진입점은 `index.html → adventure.js`다. 기존 `docs/PRD.md`, `docs/TRD.md`에는 이전 MVP 구조가 남아 있으므로 구현 상태 판단은 현재 adventure 모듈을 기준으로 한다. 이 설계는 기능 구현 전 명세이며, 아래 완료 기준은 새 구현의 검수 기준이다.

## 1 설계 목표와 범위

학생이 “내가 바꾼 조건 때문에 이 결과가 달라졌다”, “시간을 넘겨 보니 같은 개체인지 다음 세대인지 알겠다”, “내가 찾은 부분을 증거로 설명할 수 있다”라고 말할 수 있어야 한다.

상호작용마다 관찰할 정보, 학생의 결정, 반응, 남길 증거를 연결한다. 끌기 자체를 필수 과제로 만들지 않는다. 주요 흐름은 **예상 → 조작 → 변화 관찰 → 증거 저장 → 설명과 수정**이다.

태블릿의 장점은 관찰 대상 위에 직접 손을 대고 렌즈·시간 손잡이·관찰핀을 다루는 데 둔다. 한 손가락으로 모든 핵심 활동이 가능하고, 같은 기능을 탭·키보드·마우스로도 사용할 수 있게 한다. 카메라, 마이크, 기울기 센서, 로그인, 서버 기능은 이번 범위에 포함하지 않는다.

## 2 전체 학습 흐름

| 활동 | 학생의 핵심 행동 | 화면에서 일어나는 변화 | 다음 활동에 전달하는 증거 |
|---|---|---|---|
| 01 잎사귀 속 작은 생명 | 이동 렌즈로 관찰하고 특징 부분에 표시 | 손가락 위치에 따라 확대 영역 변화 | 확대 위치와 표시가 담긴 관찰 카드 |
| 02 끊어진 한살이 필름 | 순서 구성 후 두 모습의 차이 표시 | 같은 관찰 도구로 확대·비교, 다음 세대 연결 | 전후 비교 카드와 설명 |
| 03 두 씨앗의 공정한 출발 | 알아볼 조건과 예상 정하기 | A/B에서 달라진 조건만 강조 | 첫 실험의 조건과 예상 |
| 04 흙 속에서 일어난 일 | 시간 탐색, 사진 저장, 조건을 바꾼 새 실험 | 이전·새 실험을 같은 경과 시간으로 비교 | 조건 차이·관찰 시점·생각 수정 카드 |
| 05 온실 탐정의 실험 | 센서로 조건 확인 후 한 조건 바꾸기 | 조건 변화와 센서 상태가 함께 반응 | 온실 조건과 예상 |
| 06 식물이 보낸 구조 신호 | 특징 표시, 돌봄 선택, 시간 경과 관찰 | 돌봄 전후를 구분한 변화와 새 관찰 지점 | 진단 근거와 돌봄 전후 기록 |
| 07 같고도 다른 생명의 시간 | 동물 단계 비교, 식물의 다음 해 봄 탐색 | 같은 개체와 새 개체가 표식으로 구별 | 두 식물의 다음 봄 비교 카드 |
| 08 생명 정원의 새 이웃 | 기준에 따라 분류하고 관찰 증거 연결 | 분류와 선택한 증거를 함께 확인 | 분류 기준과 근거 카드 |
| 09 내가 만든 한살이 이야기 | 기록 배치, 설명 작성, 과정 재생 | 실제 관찰 상태를 복원하는 발표 카드 | 정적 PNG와 앱 안의 재생 가능한 책 |
| 10 다시 움직이는 생명 시계 | 대표 증거를 고리에 연결하고 실제 관찰 계획 세우기 | 내 기록의 짧은 재생과 구역 복원 | 완성한 책과 교실 밖 관찰 계획 |

기존 각 활동의 두 단계는 유지한다. 재실험처럼 세부 과정이 필요한 활동에는 내부 소단계를 두고, 상단에 동시에 많은 단계 버튼을 노출하지 않는다. 자유 탐색은 필수 경험을 마친 뒤 선택할 수 있다.

## 3 대표 장면 하나 씨앗 재실험

### 첫 실험

03에서 씨앗 종류·개수·흙·용기와 질문 이외의 조건을 같게 준비한다. 물 또는 온도 중 한 조건을 골라 A/B에 차이를 둔다. 잘못된 설계에서는 달라진 조건을 나란히 강조하고 “무엇 때문에 달라졌는지 알려면 한 조건만 바꿔 보자”라고 안내한다.

예상 선택지는 A, B, 둘 다, 둘 다 아님, 아직 모르겠어로 둔다. 예상의 정오로 진행을 막지 않는다. 짧은 예상 이유는 선택 기록으로 둔다. 실험 시작 시 조건을 고정한 사본을 저장한다.

04에서 시간 손잡이, 재생·멈춤, 이전·다음 시점 버튼으로 모형의 경과 시간을 탐색한다. 화분 모습, 흙 속 단면, 시점 표시가 함께 변한다. 기존 0~7일은 모형 속 경과 시간으로만 사용하고 “실제 자라는 속도는 다를 수 있어요”를 조작부 가까이에 표시한다. 움직임 줄이기에서는 상태를 즉시 교체한다.

처음, 변화가 드러나는 중간, 마지막의 A/B 사진을 남긴다. 미리 지정한 세 버튼을 누르는 방식 대신 학생이 시점을 선택하고, 부족한 기록의 의미를 알려준다. 사진에는 시점과 조건이 자동으로 붙는다.

### 조건을 바꾼 새 실험

첫 실험의 관찰과 결론을 저장한 뒤 `조건 바꿔 보기`를 제공한다. 예시는 첫 실험의 물 없는 B 화분을 복제하고, 새 실험에서는 물을 주는 것이다. 같은 씨앗을 중간에 되살리는 연출과 혼동하지 않도록 “새 씨앗으로 처음부터”를 명시한다.

1. 이전 실험에서 비교할 화분을 고른다.
2. 그 화분의 조건을 복제한 새 실험 초안을 만든다.
3. 물 또는 온도 한 조건만 바꾼다. 다른 조건과 출발 상태는 유지한다.
4. 이전보다 변화가 있을지 예상한다.
5. 새 실험을 시작하고 이전 화분과 새 화분을 같은 경과 시간으로 비교한다.
6. 차이가 보이는 시점을 저장하고, 내 예상이 유지됐는지 바뀌었는지 표시한다.

이 화면의 비교 단위는 **첫 실험의 선택한 화분 ↔ 새 실험의 화분**이다. 새 A/B 두 화분을 모두 같은 조건으로 만들고 기존 공정 실험 검사를 억지로 통과시키지 않는다. 첫 A/B 실험과 재실험 비교는 별도의 유효성 규칙을 사용한다.

시간을 되감는 것은 저장된 모형의 관찰 시점을 옮기는 행동이다. 과거를 수정하거나 실제 생물이 거꾸로 자라는 의미가 아니다. 저장된 조건은 그대로 유지한다.

```text
┌ 이번 질문: 물이 있으면 어떻게 달라질까?       기록함 ┐
│ 바뀐 조건: 물 없음 → 물 있음 / 나머지는 같음          │
├──────────────────────┬──────────────────────┤
│ 이전 실험 B          │ 새 실험              │
│ 물 없음 · 따뜻함     │ 물 있음 · 따뜻함     │
│                      │                      │
│ 화분 + 흙 속 단면    │ 화분 + 흙 속 단면    │
│                      │                      │
├──────────────────────┴──────────────────────┤
│ ◀ 이전 시점   재생/멈춤   ━━━●━━━━   다음 시점 ▶     │
│ 모형 속 4일째                    이 차이 기록하기    │
├─────────────────────────────────────────────┤
│ 처음 예상: …  관찰: …  지금 생각: …       기록 완료  │
└─────────────────────────────────────────────┘
```

완료 조건은 유효한 첫 실험, 세 시점 기록, 질문과 연결한 결과 설명, 유효한 재실험 1회, 같은 시점의 비교 증거 1개, 생각 유지·수정 선택이다. 예상을 틀렸다는 이유로 감점하지 않는다. 자동 판정은 조건과 증거 연결까지만 하며 자유 문장의 과학적 타당성은 교사가 확인한다.

## 4 대표 장면 둘 다음 해 봄 비교

07의 식물 단계는 봉선화와 사과나무를 한 화면에 나란히 배치한다. 공통 계절 다이얼로 첫해 봄 → 여름 → 가을 → 겨울 → 다음 해 봄을 탐색한다. 각 식물을 번갈아 선택하는 현재 구조는 비교 화면으로 바꾼다.

학생은 시작 시 각 개체에 표식을 붙인다. 봉선화의 원래 개체에는 `봉선화 1`, 씨앗에서 시작하는 다음 개체에는 `봉선화 2`처럼 다른 표식을 쓴다. 사과나무에는 다음 봄에도 같은 표식이 남는다. 색과 글자·형태를 함께 사용한다.

겨울에서 다음 봄으로 넘어가기 전에 “내가 표시한 생물은 어떻게 됐을까?”를 묻는다. 학생이 예상한 뒤 다이얼을 넘기면, 두 식물의 차이가 같은 화면에서 나타난다. 봉선화의 씨앗에서 새 개체가 시작되는 과정과, 사과나무의 같은 줄기에서 새잎이 나오는 모습을 각각 강조한다. 개체가 사라진 자리에 동일한 그림을 다시 띄워 같은 개체처럼 보이게 하지 않는다.

다음 봄에는 `같은 개체`, `다음 세대` 표식을 대상에 놓고 겨울·다음 봄을 오가며 근거를 찾는다. 바로 정답 설명을 보여주기보다 이전에 붙인 개체 표식과 씨앗을 다시 보도록 안내한다.

```text
┌ 다음 해 봄에 누가 돌아왔을까?                  기록함 ┐
├──────────────────────┬──────────────────────┤
│ 봉선화               │ 사과나무             │
│ 원래 개체의 기록     │ 같은 줄기와 표식     │
│ 씨앗 → 새 개체       │ 겨울눈 → 새잎       │
│ [새 표식]            │ [처음의 표식]        │
├──────────────────────┴──────────────────────┤
│ 첫봄 ─ 여름 ─ 가을 ─ 겨울 ─ ● 다음 봄               │
│ [같은 개체] [다음 세대]          두 모습 함께 기록   │
└─────────────────────────────────────────────┘
```

완료 조건은 두 식물의 겨울·다음 봄 관찰, 개체 관계 표식 연결, 두 식물이 함께 담긴 비교 증거 1개다. 동물 비교에서는 공통 슬라이더의 같은 번호가 같은 날짜·나이라는 의미가 되지 않도록 독립 단계 선택을 제공한다. 대표 생물의 변화 자료는 구현 시 그림과 문구를 함께 감수한다.

## 5 나머지 활동의 구체적 변경

### 관찰과 한살이 비교

01의 렌즈는 대상 위를 이동하며 해당 위치를 확대한다. 손가락이 확대 내용을 가리지 않도록 렌즈의 확대창을 접촉점 위쪽에 두고, 가장자리에서는 화면 안으로 이동시킨다. 확대·축소 버튼을 기본 제공하고 핀치는 보조 조작으로 둔다.

알·애벌레·번데기·어른벌레의 이름을 수집하는 것에 더해, 네 모습을 관찰하고 서로 다른 두 모습에서 특징 부분을 표시한다. 관찰 카드는 대상 ID, 확대 범위, 핀 위치, 내 설명을 보관한다. 대상 이름은 가리지 않되 특징 정답 설명은 관찰 후 요청할 수 있게 한다. 찾기 과제가 시력 테스트가 되지 않도록 보기 쉬운 크기와 힌트를 제공한다.

02는 순서 구성 후 나란히 보기와 겹쳐 보기 중 선택한다. 학생이 전후 그림에 대응하는 표시를 남기고 “날개”, “몸의 모양”처럼 비교한 기준을 고른다. 단순히 손잡이를 한 번 움직인 것으로 비교를 완료하지 않는다. 다음 세대의 알은 순환 화살표로 연결하되 어른벌레가 알로 되돌아가는 그림은 사용하지 않는다.

### 센서와 돌봄

05의 가상 센서는 모형 조건에 연결한다. 물 조건을 바꾸면 수분 표시가, 빛 조건을 바꾸면 밝기 표시가 즉시 반응한다. 실제 하드웨어 측정값이나 정밀한 수치처럼 표현하지 않고 `촉촉함/마름`, `밝음/어두움`과 같은 상태로 표시한다.

흙과 빛을 확인하는 도구는 위치에 맞게 사용할 수 있지만 설치 횟수를 채우는 반복은 줄인다. 공정 비교를 위해 바꾼 조건 하나와 유지한 조건을 표시한다. 첫 구현에서는 빛 방향이나 위치에 따른 생장 물리 모형을 추가하지 않는다.

06은 약해진 모습에서 근거 두 곳을 표시하고 돌봄 도구를 선택한다. 돌봄 직후에는 조건과 센서가 변하고, 식물 그림은 곧바로 건강한 모습으로 바뀌지 않는다. 이후 시간 손잡이를 움직이면 검수된 단계 자료로 돌봄 뒤 변화를 관찰한다. 기존 조직이 즉시 원상복구되는 표현을 피하고 새로 관찰되는 변화에 주목하게 한다.

부적절한 도구를 골랐을 때 자동 정답으로 교체하지 않는다. “이 방법으로 부족한 조건이 달라졌을까?”와 현재 센서 상태를 보여준다. 학생은 도구를 바꿀 수 있다. 적절한 돌봄과 전후 증거가 연결되면 다음으로 진행한다.

### 분류와 근거

08은 카드를 놓은 뒤 근거를 붙여 `분류 확인`하는 구조다. 초안 단계의 잘못된 배치는 허용하고, 확인 시 부족한 기준과 다시 볼 기록을 안내한다. 한 카드를 여러 정원에 동시에 확정하지 않는다.

일곱 생물의 분류는 유지하되 긴 설명을 일곱 번 쓰게 하지 않는다. 동물 대표 1개, 식물 대표 1개, 새 사례인 장미에 근거를 연결한다. 실제 관찰 기록이 없는 개구리·닭 등에는 `제공 자료`라고 표시한 자료 카드를 제공한다. 앱이 제공한 자료를 학생의 직접 관찰 기록으로 부르지 않는다. 장미도 일 년 뒤 모습을 보여주는 새 자료를 근거로 활용한다.

### 이야기책과 엔딩

09는 기존 3~6장 카드, 동물·식물 포함, 설명과 비교 생각을 유지한다. 카드에는 관찰, 조건 비교, 계절 비교 등 유형 아이콘과 짧은 출처 표시를 붙인다. `과정 보기`를 누르면 해당 기록의 조건·시점·표시를 복원하고, 발표 화면 안에서 시간 탐색을 할 수 있다. 재생은 저장된 증거를 보여주며 실험 원본을 수정하지 않는다.

PNG에는 대표 장면, 조건, 시점, 내 설명을 담는다. 움직임은 현재 기기의 앱 안에서 재생되며 PNG 파일에는 포함되지 않는다. 학생에게 파일 공유만으로 인터랙티브 재생이 된다고 안내하지 않는다.

10의 고리에는 대표 증거 카드가 하나씩 들어간다. 고리를 누르면 내가 표시한 모습이나 비교 결과가 짧게 재생된다. 마지막에는 실제로 관찰할 생물, 관찰할 특징, 다시 볼 시점을 정한다. 자동 채점이나 외부 전송 없이 내 기록으로 보관한다.

## 6 화면과 시각 디자인

가로형 기본 작업 화면에서 관찰 무대를 가장 크게 배치한다. 상단에는 질문 하나, 중앙에는 대상과 비교 결과, 하단에는 조작 도구와 기록 동작을 둔다. 상시 캐릭터 사이드바를 접고 캐릭터는 시작·막힘·발견·완료 순간의 짧은 안내로 등장한다.

| 영역 | 기본 설계 | 동작 |
|---|---|---|
| 상단 | 홈/지도, 현재 질문, 진행, 도움말 | 긴 설명은 도움말에서 펼침 |
| 중앙 | 가용 본문 폭의 약 75~85%를 관찰에 사용 | A/B 또는 전후 자료를 같은 크기로 표시 |
| 기록 서랍 | 접힌 기본 상태, 기록 수와 최근 카드 표시 | 열면 관찰 영역을 가리지 않는 레이아웃으로 전환 |
| 하단 | 큰 시간 손잡이, 이전/다음, 기록 버튼 | 관찰 대상과 동시에 보이도록 배치 |
| 안내 | 한 번에 질문 또는 힌트 한 가지 | 대상 옆 표시와 연결, 정답 문구의 중복 노출 제거 |

크림색 바탕, 숲 녹색 기본 동작, 금색 발견·선택 강조를 유지한다. 이전·새 실험은 A/B 문자와 테두리·라벨로 구별하고 색만으로 의미를 전달하지 않는다. 글자는 배경 그림에 포함하지 않고 DOM으로 표시한다.

기본 본문과 주요 버튼은 18~22px, 보조 안내는 14~16px를 목표로 한다. 주요 터치 영역은 48px 이상으로 두고 최소 8px 간격을 확보한다. 실제 크기는 뷰포트별 검수로 조정하되 글자를 무조건 줄여 맞추지 않는다.

1280×800과 1024×768에서 질문, 두 관찰 대상, 핵심 시간 조작, 기록 버튼이 한 화면에 보이게 한다. 1280×720과 주소창이 있는 낮은 높이에서도 바깥 스크롤 없이 핵심 조작을 유지한다. 긴 글 편집과 기록 목록만 내부 스크롤을 허용한다. 세로 화면은 위아래 비교 배치로 전환하며 가로 회전을 강제하지 않는다. 가상 키보드가 열리면 글 편집 영역에 공간을 주고 완료 후 관찰 상태로 복귀한다.

## 7 입력과 피드백 규칙

| 조작 | 터치 기본 | 대체 조작 | 피드백 |
|---|---|---|---|
| 렌즈 | 한 손가락 이동 | 대상 탭, 방향키, 확대 버튼 | 현재 확대 범위와 관찰 대상 표시 |
| 시간 | 손잡이 끌기 | 이전/다음 버튼, 방향키 | 시점과 두 대상이 동시에 갱신 |
| 관찰 표시 | 표시 도구 선택 후 대상 탭 | 키보드로 특징 지점 선택 | 핀 생성, 취소·다시 선택 제공 |
| 조건 변경 | 조건 버튼 선택 | 키보드 선택 | 달라진 조건만 강조, 예상 결과는 미리 공개하지 않음 |
| 기록 배치 | 카드 끌기 | 카드 선택 후 위치 선택, 앞/뒤 버튼 | 놓을 자리 강조, 순서 번호 갱신 |

손가락이 닿아 있는 동안에는 가벼운 화면 갱신만 하고, 전체 화면을 매번 재생성하지 않는다. 손을 떼거나 의미 있는 시점에 도달하면 저장한다. 슬라이더를 움직이는 매 프레임마다 화면 읽기 알림을 보내지 않고 조작 종료 시 최종 시점을 알린다.

실패 시 빨간 표시와 정답 제시만 반복하지 않는다. 바꾼 조건, 선택한 근거, 다시 관찰할 지점을 구체적으로 알려준다. 설명을 읽지 못해 진행이 막히지 않도록 시각적 위치 안내를 함께 사용한다. 음향·진동은 완료 조건에 사용하지 않는다.

## 8 완료 판정과 수업 흐름

| 구역 | 필수 경험 | 통과의 근거 | 자유 확장 |
|---|---|---|---|
| 나비의 숲 | 네 모습 관찰, 두 특징 표시, 순서와 변화 비교 | 관찰 대상과 연결된 표시·설명, 다음 세대 연결 | 확대 위치 바꾸기, 추가 그림 |
| 씨앗 연구소 | 첫 A/B 실험, 세 시점, 재실험 1회 | 유효한 조건 차이와 같은 시점 비교 증거 | 다른 질문으로 새 실험 |
| 햇살 온실 | 조건 탐색, 진단, 돌봄 전후 관찰 | 조건과 특징 두 개, 적절한 돌봄, 전후 기록 | 다른 조건의 모형 관찰 |
| 사계절 정원 | 동물 비교, 두 식물 다음 봄, 분류 | 시작 방식, 개체 관계, 분류 근거 | 다른 생물 자료 살펴보기 |
| 생명 시계탑 | 기록 3~6개로 설명, 대표 증거 연결 | 내 설명과 동물·식물 비교, 실제 관찰 계획 | 재생 발표와 결과 저장 |

힌트 사용과 예상 수정에는 감점하지 않는다. 문장 길이는 빈 입력을 막는 데만 사용하며, 긴 문장이나 글자 수를 이해도의 점수로 표시하지 않는다. 기록 완료 표시는 활동 수행을 뜻하고 자유 서술의 과학적 정답 인증을 뜻하지 않는다.

수업은 다섯 구역 단위로 나눠 이어 할 수 있다. 재실험 필수 횟수는 1회이고 추가 탐색을 강요하지 않는다. 교사와 재방문 학생은 이미 완료한 활동에 바로 접근할 수 있게 하며, 지도 걷기 연출을 매번 기다리게 하지 않는다.

## 9 상태와 기록 구조

기존 JavaScript 모듈과 정적 배포 구조를 유지한다. 새 런타임 프레임워크는 추가하지 않는다. 화면별 상태와 모형 계산을 분리하고, 모형은 조건·시점·버전이 같으면 같은 결과를 반환하도록 한다.

| 데이터 | 핵심 필드 | 보존 규칙 |
|---|---|---|
| 실험 초안 | 질문, 조건, 예상, 복제 원본 | 실행 전까지만 수정 가능 |
| 실험 실행 기록 | id, 종류, 기준 실험·화분 ID, 조건 사본, 예상, modelVersion | 시작 후 조건 불변, 비교 대상은 ID로 참조 |
| 관찰 증거 | id, 출처, 실험 ID, 시점, 대상, 확대 범위, 표시, 설명 | 저장 시 원본 상태와 연결, 기존 자료를 덮어쓰지 않음 |
| 생각 수정 | 이전 예상, 관찰 증거 ID, 유지/수정, 설명 | 기록한 실험에 귀속 |
| 계절 비교 | 종, 시점, 개체 ID, 세대 관계, 비교 증거 ID | 계절 변화와 개체 정체성을 별도로 저장 |
| 돌봄 기록 | 이전 조건, 개입 종류, 개입 시점, 이후 관찰 | 개입 전 자료 보존, 이후 경과 시간 구분 |
| 이야기책 | 카드 순서, 증거 ID, 설명, 제목, 요약 | 원본 기록 삭제에 의해 깨지지 않도록 보호 |

첫 A/B 실험은 질문에 해당하는 한 조건 차이와 공통 출발 조건을 검사한다. 재실험은 기준 화분과 새 화분 사이의 한 조건 차이를 검사한다. 비교 화면에는 비교할 실험 쌍의 ID와 공통 관찰 시점을 저장한다. 현재 선택한 실험을 바꾸더라도 이미 만든 책의 카드가 다른 결과로 바뀌지 않아야 한다.

상태 버전은 3을 제안한다. `life-clock-lab.adventure.3`가 없고 기존 v2 기록이 있으면, v2를 읽어 변환하되 원본 키는 남긴다. 기존 관찰·그림·완료 상태·책을 보존하고, 기존 실험은 조건이 확인되는 범위에서 읽기 전용 기록으로 연결한다. 새 기능의 표시·재실험·예상 수정은 임의로 완료 처리하지 않는다. 기존 완료 활동은 열람 가능하게 유지하고 `새 탐구 해보기`로 보완한다.

기록 이미지를 매번 큰 base64로 저장하지 않고 조건·좌표·벡터 표시를 저장해 썸네일을 다시 만든다. 저장 실패 시 현재 작업은 유지하고 저장되지 않았음을 알린다. 기기 저장 한계를 고려해 초기 설계에서는 씨앗 실행 기록 최대 8개, 증거 최대 60개를 목표 상한으로 둔다. 도달하면 자동 삭제하지 않고 새 생성 제한과 정리 안내를 제공한다. 책이나 비교에서 참조하는 기록은 삭제를 막거나 연결 해제 절차를 먼저 제공한다.

## 11 이미지와 로딩 설계

기존 배경·캐릭터·화분 단계 이미지는 재사용한다. 추가 자산은 다음 봄의 봉선화 새 개체, 씨앗과 원래 개체의 관계를 보여줄 분리 그림, 다음 봄의 사과나무, 돌봄 뒤 관찰 단계, 확대 관찰에 필요한 세부 그림이다.

같은 개체를 비교하는 그림은 구도·기준점·크기를 맞춘다. 단순 확대 때문에 존재하지 않던 특징이 나타나거나, 계절마다 나무의 줄기 모양이 달라지는 일을 막는다. 실제 자료가 뒷받침하지 않는 성장 중간 모습을 임의로 만들지 않고, 연출상의 이동과 생물학적 변화는 구분한다. 개체 표식·화살표·핀·계절 다이얼·조건 패널은 DOM/SVG로 만든다.

지도 진입 시 다른 구역의 비교 이미지와 발표 자료를 미리 전부 받지 않는다. 활동 진입 때 해당 장면을 로드하고, 진행 방향의 다음 단계만 제한적으로 준비한다. 설계 목표는 최초 필수 전송량 2MiB 이하, 필수 요청 15개 이하이며 현재 측정값은 아니다. 구현 중 기존 지도 자산을 포함해 계측하고 조정한다. 선택 장식의 실패는 진행을 막지 않게 하고, 필수 관찰 그림 실패에는 파일·재시도 안내를 제공한다.

## 12 검수 기준

### 대표 경험

- 첫 실험을 마친 학생이 새 씨앗으로 조건 하나를 바꿔 실행하고, 같은 시점의 결과 차이를 저장할 수 있다.
- 새 실험을 만들어도 첫 실험 사진과 이야기책의 증거가 변하지 않는다.
- 새로고침 후에도 비교한 실험, 관찰 시점, 예상·수정 기록이 복원된다.
- 두 식물의 겨울과 다음 봄을 함께 보며 같은 개체와 다음 세대를 화면의 표식으로 설명할 수 있다.
- 렌즈로 찾고 표시한 부분이 실제 기록 카드와 발표에 동일하게 나타난다.
- 센서 조건은 즉시 변하지만 돌봄 직후 식물이 즉시 완전히 회복되는 장면은 나오지 않는다.
- 잘못된 예상 때문에 활동이 막히지 않고, 잘못된 분류는 근거를 다시 보며 수정할 수 있다.

### 조작과 화면

- 실제 iPad Safari와 Android 태블릿 Chrome에서 한 손가락으로 핵심 흐름을 수행한다.
- 드래그·탭 대체·키보드 경로 모두 같은 기록과 결과를 만든다.
- 비교 손잡이를 빠르게 움직여도 손가락을 놓친 상태가 남거나 사진 날짜와 그림이 어긋나지 않는다.
- 1280×720, 1280×800, 1024×768, 세로 회전, 주소창 변화, 가상 키보드에서 핵심 조작을 확인한다.
- 움직임 줄이기에서도 동일한 정보와 완료 조건에 도달한다.

### 검증 순서

상태·모형 단위 검사 → 기존 진행·저장 회귀 검사 → 두 대표 흐름 브라우저 검사 → 이야기책과 PNG 확인 → 실제 태블릿·교실 환경 검사 순서로 진행한다. 각 구현 단위는 프로젝트의 check/test/build를 통과시킨다. 설계 문서만 작성하는 이번 단계에는 앱 빌드 결과를 구현 검증으로 제시하지 않는다.

교실 관찰에서는 학생이 ‘정답 버튼을 기억해서 진행’하는지, ‘내 조건과 관찰 증거를 설명’하는지를 구별해 본다. 완료 속도만으로 성공을 판단하지 않고, 대표 두 장면에서 학생이 무엇을 바꿨고 무엇이 달라졌는지 자기 말로 설명하는지를 확인한다.
