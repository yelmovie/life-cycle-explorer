# 2~5 스테이지 그림 로딩 복구

사용자 화면처럼 배경을 거대한 지훈 그림으로 바꾸는 현상을 재현했다. `pic()`이 누락된 모든 그림을 `guideLook`으로 대체하고, 실패한 에셋을 세션 내내 재요청하지 않는 것이 원인이었다. 배경 외의 화분·도구가 실패해도 같은 캐릭터로 표시되는 구조였다.

## 변경

- 배경·화분·도구를 캐릭터로 대신 표시하지 않는다. 필요한 그림이 모두 준비된 뒤 활동과 입력을 연다.
- 로딩 중에는 준비 화면을 표시하고, 실패한 파일은 한 번 자동 재시도한다.
- 계속 실패하면 기록을 보존하는 복구 안내와 ‘그림 다시 불러오기’·‘숲으로 돌아가기’를 제공한다. 연결이 돌아오면 자동으로 다시 요청한다.
- 정원의 생물 이름과 시계탑 이야기 제목이 위쪽 질문에 가려지던 위치를 조정했다.

변경 코드: `field-scenes.js`, `game-app.js`, `field-room-scenes.js`. 회귀 검사: `tests/field-assets.test.js`.

## 직접 검증

내장 브라우저의 별도 저장 공간 `127.0.0.1:4208`에서 버튼과 실제 Canvas 드래그로 1~5단계를 순서대로 완주했다. 완료 상태를 주입하거나 모델 함수를 직접 호출하지 않았다.

- 씨앗: 두 화분 준비, 물·온도 두 실험, 예상, 처음·중간·마지막 사진, 근거 연결.
- 온실: 두 화분의 물·빛 센서, 관찰핀, 돌봄 전후 사진, 알맞은 도구와 시간 이동.
- 정원: 나비·개의 독립 시간과 사진, 다음 세대, 식물 이름표·겨울·다음 봄, 개체 비교, 장미·강아지 새 자료.
- 시계탑: 실제 기록 세 장, 이야기·사진 설명, 세 도움 요청에 증거 연결, 실제 관찰 약속, 엔딩.
- 2·4단계 진행 중 새로고침, 완주 후 새로고침으로 기록 복원 확인. 정상 플레이 콘솔 오류·경고 0.

별도 시험 서버 `127.0.0.1:4210`에서 배경 응답을 의도적으로 503으로 바꿨다. 수정 전 캐릭터 확대를 확인했고, 수정 후에는 복구 안내를 확인했다. 정상 응답을 복원하고 ‘그림 다시 불러오기’를 누르자 배경·화분이 복구되고 흙 드래그가 작동했다. 실제 네트워크 오프라인 전환 검사는 아니다.

사용자 주소 `127.0.0.1:4186`에서도 수정본의 2·4단계 표시를 확인했다. 이 주소의 검증은 학생 기록을 저장하지 않는 교사 미리보기로 진행했다.
