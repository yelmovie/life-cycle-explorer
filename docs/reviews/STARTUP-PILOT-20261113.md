# 생명 시계 연구실 초기 로딩 시범 적용

제목과 시작 버튼은 DOM에서 열고, 기존 인트로와 첫 임무 안내를 유지한다. 지도나 탐구 화면을 열 때만 Phaser와 장면 모듈을 병렬로 요청한다. 저장된 지도·탐구를 새로고침하면 해당 화면을 다시 연다. 오프라인 전체 저장은 첫 탐구 화면이 준비된 뒤 시작한다.

| 구간 | 일반 연결, 전 → 후 | 제한망, 전 → 후 |
|---|---:|---:|
| 첫 콘텐츠 표시 | 44 → 24 ms | 288 → 216 ms |
| 탐험 시작 버튼 준비 | 102 → 58 ms | 1,923 → 700 ms |
| 타이틀 로고 표시 | 102 → 60 ms | 2,386 → 1,402 ms |
| ‘숲으로 출발’ → 지도 표시 | 92 → 138 ms | 2,817 → 4,508 ms |
| 지도에서 첫 탐구 선택 → 탐구 화면 표시 | 231 → 231 ms | 1,928 → 1,531 ms |

Chrome 157, 1280×800, 동일 작업 트리에서 변경 전후 로컬 배포용 빌드를 교대로 측정했다. 각 조건과 빌드마다 새 브라우저 문맥 5회 중앙값이다. 성능 측정에서는 HTTP 캐시와 서비스워커를 껐다. 제한망은 10Mbps 다운로드·40ms 지연·CPU 4배 감속이다. 첫 지도 시간에는 타이틀과 인트로 시간을 포함하지 않는다. 엔진을 받는 시점이 옮겨갔으므로 첫 화면은 빨라졌지만 첫 지도는 늦어졌다. 실제 학교망 및 태블릿 측정값은 아니다.

- 첫 화면과 인트로에서 Phaser·장면 코드가 요청되지 않는 것을 확인했다.
- Phaser를 차단한 상태에서 ‘탐구부터 시작하기’를 눌러 첫 관찰로 진입했다. 915×412 화면에서 알·애벌레·번데기·어른벌레의 특징 버튼을 각각 눌러 4/4 관찰 기록을 저장했다. 탐구 완료나 보상은 추가되지 않았다. 이 화면은 첫 관찰을 이어가는 경로이며 이후 필름과 시뮬레이션에는 엔진이 필요하다.
- 차단을 풀고 다시 불러오면 원래 지도 또는 탐구가 열렸다. 그림 관찰에서 남긴 기록도 원래 탐구에 이어졌다. 지도 그림만 차단하면 지도를 거치지 않고 기존 첫 탐구로 진입했다. 엔진 응답이 뒤늦게 와도 이미 열린 그림 관찰을 덮지 않았다.
- 시작 앱과 장면 모듈을 각각 차단했다가 풀어 다시 열기 동작을 확인했다. 첫 탐구 이후 오프라인 저장이 준비되면 연결을 끊어도 새로고침으로 탐구·지도·첫 화면이 열렸다.
- 문법 검사 47개, 단위 검사 188개, 배포용 빌드 통과. 운영 배포는 하지 않았다.
