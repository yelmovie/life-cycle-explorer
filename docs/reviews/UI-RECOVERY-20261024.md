# 중단 작업 복구 · 태블릿 UI와 기록 노트 검증

검증일: 2026-10-24. 소스 서버 `http://127.0.0.1:4212`에서 Chrome의 격리된 터치 컨텍스트로 확인했다. 사용자 브라우저 프로필과 학습 저장소는 사용하지 않았고, 기존 `.tmp/field-play/earned-state.json`을 읽어 각 컨텍스트에 복제했다.

## 검증 결과

- `node scripts/qa-recovery-layout.mjs`: **48화면 통과**, JavaScript/HTTP 오류 0개.
- 1280×800, 1024×768에서 각각 24화면: 관찰실·자동 관찰 노트·그림 단계·직접 쓰는 노트·씨앗/돌봄 촬영 노트·코르크판 빈 상태/2장/편집/6장 긴 기록·사진 설명/이야기 쓰기·추가 발견 10단계·보상 스탬프 2종.
- 의도하지 않은 가로 스크롤, 모달 화면 밖 이탈, DOM 버튼의 화면 밖 잘림 없음. DOM 버튼 최소 44px 확인. 관찰실 캔버스 버튼은 1024px 화면에서도 실제 높이 44.8px 이상으로 보강했다.
- 관찰 버튼 터치 → 실제 inspected 기록 → 점진 타이핑 → 글 바로 보기 → 다음 특징 이동을 확인했다. 두 번째 특징을 살피면 해당 생물의 두 특징만 노트에 모인다.
- 직접 쓴 관찰 문장·사진 설명·이야기 제목의 저장을 확인했다. 이야기 이름/생각 작성 화면을 거친 뒤 새로고침해 제목이 유지되는 것도 확인했다.
- 사진을 한 장씩 터치하면 코르크판에 추가되고 아래 목록에서는 빠진다. 중복 없이 순서대로 2장 추가되는지 확인했다.
- 사진 설명의 기록 선택을 바꾸면 그림·제목·작성 글이 같은 기록을 가리킨다.
- 씨앗 0일 사진은 현재 두 화분의 모습과 물/온도 조건을 보여 준다. 빛 돌봄 사진은 긴 줄기를 유지하고 세 줄기 끝의 새잎만 표시한다. SVG 좌표와 contain 배율의 일치도 자동 확인했다.
- `node --test tests/field-notebook.test.js`: **4개 통과**.

## 수정한 부분

- `field-room-scenes.js`: 추가 발견 화면 호출과 필요한 에셋 로드 연결. 추가 발견을 모두 마친 보상 화면에 해당 미션의 스탬프를 표시한다.
- `field-observation-scenes.js`: 보기 버튼 높이 48→56. 복잡한 잎 배경 위 중앙 안내에 기존 밝은 라벨 스타일을 적용했다.
- `field-story-scenes.js`: 긴 제목/요약이 상단 안내·사진·우측 노트 밖으로 넘치지 않도록 미리보기에 말줄임을 표시했다. 저장 원문과 작성 모달은 유지한다.
- `field-notebook.js`, `field-notebook.css`: 빛 돌봄 새잎을 기록 이미지와 공통인 `lightRecoveryLeaves` SVG 좌표로 맞췄다.
- `scripts/qa-recovery-layout.mjs`: 격리 저장소를 쓰는 반복 검증과 화면 캡처.

추가 발견 화면의 안내·버튼 겹침 두 곳과 참고 그림을 실제 흔적으로 오해할 수 있던 표현은 담당자에게 전달했고 최종 캡처에서 수정 반영을 확인했다.
